# Security Policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

Use GitHub's private reporting on this repository (Security tab, "Report a vulnerability"), or email `william@mobilesecurityguru.com`.

Include what you can: affected version or commit, deployment surface, reproduction steps, and what an attacker gets if it works.

## What to expect

You will get an acknowledgement that the report was received. Once triaged, you will get an assessment and a fix timeline. Sponsors at the Founding tier carry a stated SLA for critical fixes; everyone else gets the fix in the same release.

Credit is offered by default and withheld on request.
